# PRD — 무엇을 · 왜

> 원문(request.md)을 옮긴 파생 문서. 요구 충족 판정 기준은 언제나 원문이다

## 문제
- `harness-template` 에는 보안 검증 역할과 게이트가 없다
- 규모별 문서 구성(소 · 중 · 대)도 템플릿에 없다

## 목표
- 템플릿을 그대로 가져온 공개 저장소에 다음을 더한다
  - 소 · 중 · 대 문서 구성
  - 보안 역할 · 서브에이전트 · 게이트
  - 실험 설계와 후보 프로젝트 기록
- 실험 결과로 템플릿을 업그레이드할 출발점을 만든다

## 비목표
- 실험 실행과 채점 도구 (후보 재현 점검 후 별도 작업)
- 원본 `harness-template` 변경 (실험 결과가 나온 뒤)
- 정답지(권고 ID · 패치 · 공격 테스트) 공개 저장소에 올리기

## 애매한 곳
- 저장소 공개 여부 (확인됨: 공개)
- 기본 틀 (확인됨: harness-template)
- 규모별 문서 구성 (확인됨: 소형 SDD · 엔티티, 중형 온톨로지 · SDD · 엔티티, 대형 온톨로지 · PRD · SDD · 엔티티)
- 저장소 이름 `harness-security-bench` (가정)
- 엔티티 문서 형식: 필드 · 관계 · 소유 권한 (가정)
- 보호 파일 `checks.sh` · `AGENTS.md` 에 보안 게이트 연결 (사람 승인 대기)

## 완료 기준
- [ ] bash .agents/checks.sh PASS
- [ ] 구성 적용 스크립트와 보안 게이트에 테스트가 있고 통과한다
- [ ] 실험 설계와 후보가 문서로 남아 있고 정답 정보가 없다
